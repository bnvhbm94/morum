# /universe 재설계 요청서 (Fable)

2026-09-23. 요청자: 운영자(nuanox). 작성: Claude Opus. 이 문서만 읽고 바로 작업할 수 있게 썼다.

## 목표

지금의 `/universe` 화면도 나쁘지 않다. 요청은 **디자인과 사용감을 둘 다 월등하게** 만드는 것이다. "조금 다듬기"가 아니라, 처음 들어온 사람이 "인터넷 전체가 이 안에 정리돼 있다"고 느끼고, 오래 써도 손에 익는 화면이 목표다.

Morum은 사람과 AI 에이전트가 함께 쌓는 공개 지식 저장소다(자세한 설명: `docs/morum-guide/drafts.md`, 설계: `docs/ARCHIVE_DESIGN.md`). 최종 규모는 카테고리 수십만, 문서 수백만을 가정한다. 지금 운영 데이터는 수십 개 문서, 주제 몇 개뿐이다.

## 새 비유: 천체 계층 (이번 요청의 핵심)

| 천체 | Morum | 예 |
|---|---|---|
| 은하 (은하단, 초은하단) | 대주제. 하위 카테고리를 품은 카테고리 | 역사, 과학, 동물 |
| 항성 | 주제. 문서를 직접 가진 카테고리 | 조선 시대, 고양이, 기후변화, Morum |
| 행성 | 문서(기록). 항성 주위 궤도에 놓인다 | "훈민정음은 1443년…" |
| 위성 | 문서에 딸린 것: 근거 연결, 수정 이력(버전), 검토 | |

규칙:
- 카테고리 깊이는 정해져 있지 않다(DAG, 다중 소속, 최상위 자유). 천체 종류는 **층 번호가 아니라 역할**로 정한다. 하위 카테고리만 있으면 은하, 문서를 직접 가지면 항성, 둘 다 가지면 중심에 항성이 있는 은하.
- 위성 중 근거는 "출처 원본"이 아니라 "이 문서가 그 출처의 어느 구절을 근거로 삼았다는 연결"이다. 같은 출처를 여러 문서가 쓸 수 있다.
- 문서 사이의 관계(지지, 반박, 정정, 파생)는 위성이 아니다. 어떻게 보여 줄지는 제안해 달라. 단, 화면 위치가 가깝다는 이유로 관계를 암시하면 안 된다(선언된 것만 보여 준다).
- `Morum` 항성은 우주 중심에 있다(`CENTER_CATEGORY_ID = 'topic:Morum'`).
- 지금 데이터는 주제가 한 층(`attributes.topic`)뿐이다. 즉 당장은 **항성과 행성만 있고 은하는 없다.** 은하는 1단계(여러 층 카테고리) 이후 생긴다. 코드는 `UniverseSource`(`src/components/universe/types.ts`)가 층을 돌려주면 은하가 자연스럽게 나타나도록 짜 달라. 필요하면 테스트용 가짜 소스로 여러 층을 확인한다.

## 항성도 하나의 문서다

항성을 고르면(클릭, Enter) 그 항성의 **설명 문서**가 열린다. 이 문서는 그 항성에 속한 행성(문서)들의 내용을 바탕으로, 처음 보는 사람도 그 주제를 이해할 수 있게 쓰인 글이다. "쉬운 글"이라는 뜻이 아니라 **그만큼 명확한 글**이라는 뜻이다. 수준을 낮추지 않는다.

데이터 약속(이번 작업에서 정한다):
- 항성 설명 문서는 평범한 기록이고, `attributes`에 `topic: "<주제 이름>"`과 `role: "star"`를 가진다. 한 주제에 여러 개면 가장 최근 것을 쓴다.
- 행성 목록에서는 `role: "star"` 기록을 빼고, 항성 자체에 붙인다.
- 설명 문서가 아직 없는 항성도 있다. 그때 보여 줄 상태를 디자인해 달라(이름, 행성 수, "아직 설명이 없다"는 사실. 설명을 지어내지 않는다).
- 설명 문서의 **내용을 쓰는 것은 이번 작업 범위가 아니다.** 나중에 에이전트가 쓰고 운영자가 검토해 올린다. 화면과 데이터 연결만 만든다.
- 읽기 화면은 기존 행성(문서) 읽기 화면과 같은 경험이어야 한다. 제목 표시, 위/아래 화살표로 문단 이동(제목도 선택 대상), 선택한 문단이 밝게 표시됐다가 약 3초 뒤 사라짐. 지금은 `src/components/spatial-explorer.tsx`의 `stepReadingParagraph`, `markReadingUnit`, `pageReading`이 이 일을 한다. 재사용하거나 공용 모듈로 옮겨도 된다.

## 사용자가 이미 정한 것 (지키기)

- 하나의 연속된 우주. 확대하면 은하 → 항성 → 행성 → 위성으로 끊김 없이 들어간다. 페이지 전환처럼 느껴지면 안 된다.
- 항성 이름은 항성 한가운데. 그 자리에는 행성이 놓이지 않는다. 이름 뒤 별빛은 숨기지 않고 어둡게 한다(지도식 글자 테두리). 이 방식은 Map of GitHub, Nomic Atlas, Mapbox 지도 라벨을 참고해 정했다.
- 제목이 있는 문서는 제목을, 없는 문서는 본문 첫 구절을 짧게 보여 준다.
- 화살표 키로 가까운 대상 선택, Enter로 들어가기, Esc로 한 단계 나오기. 문서에서 Esc를 누르면 들어온 곳으로 돌아간다.
- 배경의 장식용 별빛은 괜찮다. 단 장식과 데이터(실제 문서)가 헷갈리면 안 된다.
- 테두리 상자, 연결선, 넓은 어두운 그라데이션 가림막은 쓰지 않는다(사용자가 싫어한다). `tests/static/universe-ui.test.mjs`가 일부를 검사한다.
- 스크롤바는 보이지 않아도 된다.
- 화면 문구는 한국어이고 짧게. 기존 사이트 소개 문구의 말투는 쓰지 않는다. 문구가 필요하면 `docs/morum-guide/drafts.md`의 말투(담백한 서술체)를 따른다.

## 알려진 문제 (같이 풀어 주면 좋은 것)

- 행성 제목끼리 겹친다(예: "임진왜란…"과 "조선왕조실록…"). 지도처럼 충돌 감지로 중요한 것만 먼저 보이고, 확대하면 나머지가 나타나게 하면 좋겠다.
- 멀리 떨어져 있어 찾기 어려운 문서가 있었다.
- 카메라 이동, 확대의 손맛(관성, 속도 곡선, 트랙패드 핀치, 마우스 휠) 전반.

## 기술 제약

- Next.js 16.3.5 App Router, React 19.3, TypeScript strict. Next 관련 코드를 쓰기 전에 `node_modules/next/dist/docs/`의 해당 안내를 읽는다(`AGENTS.md`).
- 렌더링은 Canvas 2D + 접근 가능한 DOM 버튼. **WebGL, three.js, 새 런타임 의존성은 쓰지 않는다.** 꼭 필요하다고 판단되면 구현하지 말고 이유와 함께 제안만 남긴다.
- 문서가 수백만이 되어도 버틸 구조: 화면에 보이는 것만 그리고 불러온다. DOM 버튼 수 상한(`MAX_DOM_CATEGORIES`)을 유지한다.
- 레이아웃은 결정적이어야 한다(같은 데이터 → 같은 위치, `layoutSeed`). 유사도로 배치를 지어내지 않는다.
- rAF로 그리고 ref로 상태를 들고 있는 현재 구조는 바꿔도 되지만, 휴대폰 폭(약 375px)에서도 동작해야 한다. 좌우 16px 여백, 가로 스크롤 없음. 키보드와 스크린리더로도 쓸 수 있어야 한다. `prefers-reduced-motion`을 존중한다.
- 바꿔도 되는 곳: `src/components/universe/*`, `src/app/universe/*`, `src/lib/universe-data.ts`, 읽기 화면 공용화를 위한 `src/components/spatial-explorer.tsx`와 `src/app/globals.css`의 관련 부분, 그리고 관련 테스트(`tests/unit/universe-*.test.mjs`, `tests/static/universe-ui.test.mjs`). 새 파일 추가는 자유.
- 건드리지 않는 곳: `src/server/**`, `supabase/**`, `/api`, 계약(2.1.0), `MY THOUGHT/`, `next-env.d.ts`, `.claude/`. DB 마이그레이션은 만들지 않는다.
- 커밋하지 않는다. 배포하지 않는다. 운영 API에 쓰지 않는다(읽기는 괜찮다).
- 개발 서버는 이미 `http://localhost:3000`에서 돌고 있다. 끄거나 다시 띄우지 않는다. `/universe`에서 확인한다. 브라우저 도구로 확인할 때 탭이 뒤에 있으면 애니메이션 프레임이 멈추므로 최종 상태로 판단한다.

## 확인 명령

```
npx tsc --noEmit -p .
npm run -s test:unit
npm run -s test:static
```

셋 다 통과해야 한다. 새 기하/레이아웃 로직(궤도 배치, 라벨 충돌, 천체 종류 판정)은 `tests/unit/`에 단위 테스트를 붙인다.

3. 사용감에서 달라진 점(조작, 키보드, 카메라).
