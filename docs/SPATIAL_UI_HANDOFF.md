# Spatial UI handoff

The home route now renders `SpatialExplorer` from `src/components/spatial-explorer.tsx`. It consumes the committed adapter in `src/lib/spatial-data.ts`; no mock document array, database access, credential, route, or migration was added.

## Implemented behavior

- Home and current-scope search results occupy deterministic integer coordinates in a borderless, line-free dotted field. One world layer receives `translate3d`; pointer movement is coalesced through `requestAnimationFrame`, and node lightness follows continuous distance from the viewport center.
- Drag selection, decaying inertia, click suppression after a drag, pointer capture/cancel, deterministic directional-arrow selection, Enter-to-read, editable/IME keyboard guards, and reduced-motion shortcuts are implemented.
- **Activation model (replaces the earlier “click the already-selected node to read” rule).** A single click on any node — selected or not — only selects it and smoothly centers the camera on it, exactly like an arrow key. A single click never opens the reader. A genuine fast double-click/double-tap opens the document; because the first click of the pair already centers it, an off-center document is centered before it opens. Enter still opens the centered/selected node.
- Double activation is detected in the node button's single `onClick` handler from two ORed signals: `event.detail >= 2` (the browser's native double-click, honoring the OS double-click interval) and a `lastTapRef` fallback for the same node index within `DOUBLE_TAP` (340 ms). The fallback exists because touch-synthesized clicks do not accumulate `detail` and `dblclick` is not reliably delivered from touch taps. `lastTapRef` is cleared on drag completion, arrow-key navigation, and each page/search load. The second `mousedown` of a double-click calls `preventDefault()` only when `event.detail >= 2`, which suppresses the text-selection side effect without disturbing focus or the first click.
- **Pointer capture is acquired lazily, and this is load-bearing.** `setPointerCapture` is called on the first `pointermove` that crosses `DRAG_THRESHOLD`, not on `pointerdown`. Capturing on pointer down retargets `pointerup` *and the compatibility `mouseup`/`click`* to the capture element, so the node button's `onClick` never fired at all — clicking a document did nothing, and Enter was the only way to open one. Releasing inside the `pointerup` handler is too late to undo this. Do not move the capture call back to `pointerdown`. Known trade-off: the bottom search control is a sibling of `.spatial-viewport`, so a drag begun within `DRAG_THRESHOLD` of that control while the search input is focused can miss its inertia; `markActive()` normally hides the control (`pointer-events: none`) on pointer down, which makes this nearly unreachable in practice.
- The bottom search control debounces for 1000 ms, aborts superseded requests, rejects stale generations, returns to home data on an empty query, stays visible while focused/composing, and otherwise returns after two idle seconds. Search status is described as search results without inferring logical relationships.
- Reading fetches the exact version and bounded relations together. Left and right columns use the adapter's relation semantics, show at most four items per side, keep non-hierarchical relations in “기타 관계”, expose fixed/raw/history routes, and disclose when more relations exist. Side navigation fetches the next full version before replacing the center. Escape and the 34 px glass close control return to the preserved map state.
- Desktop and mobile reader layouts, touch scrolling, focus-visible treatment, and reduced-motion styles are included. The existing dedicated `/records`, `/versions`, `/search`, `/objects`, and `/sources` routes remain intact.
- The bottom search control and the 34 px close control use a liquid-glass treatment rather than a filled translucent bar: a weak internal tint (`rgb(255 255 255 / .045)`), `backdrop-filter: blur(20px) saturate(170%) brightness(1.3)`, layered inset top-highlight/bottom-bounce/perimeter-ring shadows in place of a flat border, and a blurred `::before` specular patch. The `saturate`/`brightness` lift is what makes the blur legible at all: the field is `#050505`, so `blur()` alone resolves to black and the old `rgb(25 25 25 / .58)` fill masked what little it produced. `globals.css` is covered by a static assertion banning `gradient`, so these effects use flat fills, blurred pseudo-elements and inset shadows only. Sizes, geometry, the hide/show transition and the close control's 34 px size and `::after` hit area are unchanged.
- `.spatial-reader` is opaque `#050505`. It was previously `rgb(5 5 5 / .98)`, which let document-space text behind it read through clearly and overlap the reading column.
- Side-relation navigation inside the reader (clicking a left/right relation, not the initial map-to-reader open) now cross-fades: the previously centered document is kept mounted and marked `inert`/`aria-hidden` while the newly centered document slides in from the clicked side over 420 ms, then the outgoing panel is unmounted. This replaced reliance on restarting the section-level `animation-name` on `data-direction` change, which does not retrigger for two consecutive same-direction relation opens. `prefers-reduced-motion` and the existing reduced-motion ref skip the two-panel transition entirely and render the new document directly. See `SpatialReader`/`ReaderStage` in `src/components/spatial-explorer.tsx` and `.reader-slide`/`@keyframes reader-slide-left|right` in `src/app/globals.css`.

## 2026-09-23 update: relation-aware layout, dock, fonts

- **Placement is now relation-aware.** `layoutEdges`/`layoutNodes` in `src/lib/spatial-data.ts` place a node next to an already-placed related node when both ends are version nodes on the current page: `supports` puts the supporter one cell left of the supported target; `corrects`/`derived_from`/`depends_on` put the referenced target one cell left of the referencing node (so a correction sits right of what it corrects). Occupied cells fall through to the same column at y±1, ±2; unrelated nodes keep the old spiral order. Node 0 stays at (0,0). The function is pure and deterministic. Relations come from `response.context.relations` for searches and from one `POST /context` (first five nodes, depth 1) after the home page loads; a failed context request only changes the status sentence.
- **The status line states the placement basis** (`최근순 배치`/`관련도순 배치` plus `관계 N개 반영`, `관계 없음`, or `관계 정보를 불러오지 못함`) so proximity is never mistaken for an undeclared relation.
- **No camera teleport.** After a page loads, `center(0)` animates from the current camera in an effect keyed on `pageGeneration`; node keys stay `node.key`, so a document that survives a re-search keeps its element and focus and slides to its new cell (`left`/`top` transition, 320 ms), while newly mounted nodes fade in via `spatial-node-in`. A review caught an earlier `${pageGeneration}:${key}` key that remounted everything; do not reintroduce it. Both transitions are disabled under reduced motion.
- **Flick velocity** uses the last three pointer samples within 80 ms (weights 2:1:1); a paused release yields no inertia. `MAX_FLICK` and the `.92` decay are unchanged.
- **Bottom dock.** `.spatial-dock[data-hidden]` wraps `.spatial-status` and `.spatial-search`; it stays visible while loading, on failure, or while the input is focused. The old fixed top-left status and the `::before` specular patch are gone; the pill keeps one `backdrop-filter`.
- **Fonts are self-hosted** in `public/fonts/` (Pretendard Variable v1.3.9; Source Serif 4 Variable latin + latin-ext, both OFL 1.1, see `THIRD_PARTY_NOTICES.md`) via `@font-face` in `globals.css`; `layout.tsx` preloads Pretendard with `ReactDOM.preload` (literal `<link rel="preload">` is unsupported in this Next version's App Router metadata). Korean serif still falls back to system fonts.
- **Verified live** (Chrome pane, `localhost:3000`, five real records): relation `corrects` placed the corrected version at (-1,0); single click selected/centered without opening; double-click opened the reader with both fonts loaded and no text selection; a 120 px flick travelled ~250 px with the reader closed; arrows + Enter opened the neighbor; search `우주` returned two nodes with the relation reflected and an empty query restored home; 375×812 had no horizontal overflow and the dock measured 343 px at x=16; no console errors. Caveat: the browser pane throttles `requestAnimationFrame` to a few frames per second unless a screenshot is being taken, so animation timing cannot be judged there, only end states.

### Live-data verification of the activation model

A later session had a working `.env.local` and a Supabase project holding real documents, so the interaction changes above were exercised in Chrome against live data (five real records), not fixtures:

- Single click on an off-center node: selected it and centered it exactly (`translate3d(-430px, 0px, 0px)`), reader stayed closed.
- Single click on the already-centered node: reader stayed closed. This is the behavior change; under the previous rule it would have opened.
- Fast double-click: reader opened with the correct document, and no text was selected.
- Two clicks separated by ~1.5 s: reader stayed closed.
- Drag and release: reader stayed closed, no text selection, and inertia decayed smoothly after release.
- Arrow key then Enter: selection moved to the neighbor, centered exactly, and Enter opened it.
- 375 × 812: no horizontal overflow (document scroll size equals the viewport), search control 343 px at x=16, drag and inertia intact.
- Search: a debounced query returned two real hits and re-laid them out from the center; the control hid during activity and returned after the idle interval.
- No application errors in the browser console. `npm run typecheck`, `npm run test:static` (18/18) and `npm run build` all passed after the change.

Not verified: a real finger double-tap on a physical touch device. The browser-automation harness delivers mouse clicks even under touch emulation, so the touch fallback was exercised by dispatching two `detail: 1` clicks 150 ms apart (opened) and 800 ms apart (did not open), which covers the code path but not the real gesture. Relation-transition slide behavior against real neighbor data, history, and back/forward were also not re-exercised in that session. The previously documented missing external reference fixture and four service-suite workspace/path failures remain unchanged.
