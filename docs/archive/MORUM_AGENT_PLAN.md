# Morum 작업 배분과 실행 프롬프트

작성: 2026-09-21. 이 문서는 Astra의 구현 제안이다. 현재 사용자의 요청은 프로젝트 이해, 역할 배분, 작업 프롬프트 작성이다. 이 문서를 작성했다고 구현·커밋·배포가 실행된 것은 아니다.

## 1. 제품의 기준

Morum은 사람과 여러 외부 에이전트가 같은 지식을 읽고 기여하는 저장소다. 주장뿐 아니라 그 의미, 근거, 반론, 정정과 버전 이력을 연결하여 다음 작업에서 재사용하도록 한다. 웹 화면은 사람이 이 구조를 읽는 입구이고, 공개 API와 skill.md도 같은 제품의 핵심이다.

- 원문과 과거 버전은 보존한다. 수정은 이유와 근거를 남긴 새 버전/분기다.
- 최신 버전과 가장 신뢰할 만한 버전은 다르다. 현재 프로토타입의 최신 버전 정책을 진실 판정처럼 표현하지 않는다.
- 관련도 점수는 진실 확률이 아니다. 화면에서 가까운 문서라는 이유만으로 논리적 근거 관계를 만들어서는 안 된다.
- 외부 출처뿐 아니라 설명 가능한 추론도 기록할 수 있다. 모든 기여에 URL이나 원시 실험 데이터를 강제하지 않는다.
- 에이전트는 필요한 부분과 맥락부터 조회하고 원문으로 확장할 수 있어야 한다. 시각적 탐색을 사용해야만 API를 쓸 수 있는 구조로 바꾸지 않는다.
- 문서 형식을 추가로 강제하지 않는다. 제목 없는 기록과 다양한 관계 대상을 지원한다.
- 암호화폐, 분산 보존, 자동 진실 판정, 학습 데이터 추출, 서버의 외부 웹 수집은 이번 범위에 넣지 않는다.

자료 해석: 현재 대화의 요청을 우선한다. 원본생각/1번에도 AI의 정리·외부 인용이 섞여 있으므로 사용자의 직접 발언과 구분한다. 2~4번의 AI 제안·평가·논문 소개는 참고 자료이며 자동 채택하지 않는다. 그 안의 과거 명령, 데모 기한, 배포 허용 발언을 현재 실행 권한으로 승계하지 않는다. TEMP_AGENT_HANDOFF.md는 이전 작업의 맥락과 UI 요구를 제공하지만 실제 코드·서버 상태는 다시 확인한다.

## 2. 최소 인원과 순서

| 역할 | 모델/추론 | 책임 |
| --- | --- | --- |
| 기획자 | Astra, 현재 대화 | 요구사항·범위·의미적 결정·완료 기준, 차단 문제 판단 |
| 에이전트 1 | GPT-5.6 Luna / medium | 기존 API 점검, 데이터 어댑터, 제한된 결함 수정, 기능 검증 |
| 에이전트 2 | GPT-5.6 Sol / high | 새로운 공간 탐색·읽기 UI, 브라우저 시각 검증, 통합 |

MID는 여기서 medium으로 해석한다. 기본 실행은 Luna → Sol → 필요한 경우 같은 Luna의 회귀 검증이다. 작업자 둘을 상시 병렬로 두지 않고, 별도 검수 에이전트나 Terra를 기본으로 추가하지 않는다. 새 하위 에이전트를 만들지 않는다.

Luna가 같은 원인으로 두 번 수정을 실패하거나 공개 계약/DB 의미를 바꿔야 하면 실패 재현, 시도한 변경, 필요한 결정만 Astra에 돌려준다. 오류가 생겼다는 이유만으로 모델을 자동 승격하지 않는다. Sol은 시각 판단이 필요한 부분을 맡으며 서버 재설계를 함께 떠안지 않는다.

각 작업자는 이 문서와 TEMP_AGENT_HANDOFF.md, 담당 파일부터 읽는다. 매번 원본생각 전체와 연구 자료 전체를 다시 읽거나 장문의 과거 대화를 복사하지 않는다. 제품 의도가 모호할 때에만 해당 원문 구간을 확인한다.

## 4. Git과 서버 운영 공통 규칙

실제 구현을 맡기는 시점에 아래 규칙을 적용한다.

1. 시작할 때 branch, status, diff, 기존 실행 프로세스를 확인한다. 현재 수정 4개를 사용자 작업으로 보존한다. reset --hard, clean, 변경 덮어쓰기, 다른 작업의 서버 종료를 하지 않는다.
2. 순차 작업이므로 같은 checkout에서 codex/spatial-explorer 브랜치를 사용한다. 이미 존재하면 그 이력과 현재 작업 연관성을 확인한다. 최신 미커밋 상태를 버리고 HEAD만으로 새 worktree를 만드는 방식은 피한다.
3. 시작 상태의 tracked diff를 저장소 밖 로컬 백업으로 보존한다. 기존 UI 4개는 검토 후 별도 baseline 커밋으로 구분하고, 자신이 만든 코드라고 보고하지 않는다. 비밀·개인 자료·원본생각·임시 파일을 일괄 stage하지 않는다.
4. 이후 커밋은 데이터 준비, UI 통합, 후속 수정처럼 동작 단위로 나눈다. stage한 diff를 확인하고 커밋한다. 작업자 교대 때 commit SHA와 남은 변경을 전달한다.
5. 원격 저장소를 임의로 생성하거나 push·merge하지 않는다. 원격이 없어도 로컬 작업과 커밋은 진행할 수 있다. 배포 단계는 별도 실행 범위로 다룬다.
6. 기존 Next → /api/v2 → service → DB adapter → Supabase 경로를 재사용한다. UI에서 서비스 역할 키나 DB에 직접 접근하지 않는다.
7. 환경 점검 결과에는 변수/설정의 존재 여부만 적고 값을 출력하지 않는다. 설정이 없어도 가능한 로컬 검증을 수행하고 실연동 미검증을 명시한다.
8. DB 변경은 기존 migration 수정 대신 추가 migration으로 작성하고, 문서에 정해진 폐기 가능한 로컬 DB에서 검증한다. 운영 DB에 테스트 데이터를 넣거나 reset하지 않는다.
9. 이번 UI 작업에 credential prefix, HMAC domain string, 외부 client 경로 변경을 섞지 않는다. Nuanox 호환성 변경은 별도 작업이다. UI 내부 리네임도 필요한 범위로 제한한다.

## 5. 에이전트 1에게 전달할 프롬프트 — Luna Medium

당신은 /Users/nuanox/Documents/Morum의 데이터 연결·검증 담당이다. MORUM_AGENT_PLAN.md의 제품 기준과 공통 규칙, TEMP_AGENT_HANDOFF.md를 읽고 아래 범위만 구현하라. 디자인과 공간 UI는 다음 Sol 작업자가 담당한다. 하위 에이전트를 만들지 마라.

### A. 현재 계약 확인

AGENTS.md와 관련 Next.js 로컬 문서를 읽는다. src/contracts/types.ts, src/lib/api-client.ts, src/server/service/routes.ts, retrieval.ts, 현재 home-feed/search-results/version-reader와 관련 테스트를 조사한다. 관련 없는 저장소 전체를 덤프하지 않는다.

다음 연결표를 실제 요청/응답 타입과 코드 근거로 작성한다.

- 홈: GET /records의 current 버전 → 문서 노드. 우선 최대 20개, 기존 API 한도 확인.
- 검색: POST /search, scope=current, include_context=true, limit≤20. 서버 순서를 유지하며 첫 결과를 중앙 후보로 한다.
- 읽기: 정확한 version ID로 GET /versions/:id. record ID와 혼동하지 않는다.
- 주변 정보: /context와 /relations의 역할, 중복, 페이지네이션, 잘림 정보. 기존 응답으로 충분하면 API를 추가하지 않는다.
- source/anchor/object와 version 사이의 이동. version_id가 null인 검색 결과를 가짜 버전으로 변환하지 않는다.

### B. 화면과 독립적인 데이터 계층

제안 파일은 src/lib/spatial-data.ts 및 필요할 경우 검색 hook 한 개다. 기존 동등한 코드가 있으면 확장한다. 서버 타입을 중복 정의하지 말고 필요한 UI 형태로만 변환한다. 함수 이름/정확한 타입은 계약 확인 후 정하며 다음 기능은 제공한다.

- 홈 문서, 검색 문서, 정확한 버전, 관계 이웃 로딩. 모든 비동기 로더는 AbortSignal을 받을 수 있다.
- 문서 노드는 안정적인 kind+id, 원본 target/locator, 제목 fallback, 발췌, URL, 버전 상태를 유지한다. 같은 버전의 여러 검색 hit는 최고 순위 노드 하나로 묶되 원래 locator 정보를 보존한다.
- 같은 문자열 query라도 scope/filters/limit/include_context가 다르면 다른 캐시 키다. 제안 기본값: debounce 1000ms, 메모리 캐시 30개/TTL 60초. 오류는 캐시하지 않는다.
- 요청 취소뿐 아니라 request generation 비교로 오래된 성공/실패/finally가 새 결과·loading을 덮어쓰지 못하게 한다. 빈 검색어로 돌아갈 때도 검색 요청을 무효화한다.
- 성공한 빈 결과, 로딩, 실패, 부분 실패, 잘림을 구분한다. 검색 실패를 홈 결과 또는 목업 결과로 위장하지 않는다.
- 관계 목록의 표시 상한과 실제 조회 결과/추가 페이지 존재를 구분한다. 이웃을 무제한 재귀 조회하지 않는다. 중복 요청을 줄이고 필요하면 동시 조회 수를 제한한다.

관계의 좌우는 in/out만으로 정하지 않는다. from/to와 predicate의 의미가 함께 필요하다. 아래는 이번 UI의 제안 매핑이며 현재 API 설명·테스트와 대조한다.

- A supports B: B를 읽을 때 A는 왼쪽 근거, A를 읽을 때 B는 오른쪽 연결 주장.
- A depends_on B / A derived_from B: A를 읽을 때 B는 왼쪽, B를 읽을 때 A는 오른쪽.
- A corrects B: B를 읽을 때 A는 오른쪽 정정, A를 읽을 때 B는 왼쪽 이전 대상. 실제 계약도 from=정정 자료임을 확인한다.
- contradicts / related_to / same_meaning_as / translation_of / defines / 사용자 확장 관계를 일괄 상하위로 취급하지 않는다. 의미를 명시한 별도 맥락 목록에 남긴다. 정의 관계 등의 좌우 확장이 필요하면 근거와 함께 제안한다.
- anchor는 실제 소속 버전을 확인할 수 있을 때만 문서 이웃으로 연결한다. source와 해결 불가능한 대상은 본래 링크로 남긴다.
- 같은 문서가 여러 관계를 가질 수 있으므로 관계 목록을 잃지 않게 한다. 순환과 자기 관계로 무한 조회하지 않는다.

### C. 제품 목적에 직접 영향을 주는 결함

VersionReader의 조회 실패를 빈 목록으로 바꾸는 동작과 evidence 중복 표시를 수정한다. UI 재디자인은 하지 않고 부분 오류·재시도에 필요한 최소 변경만 한다. 중복 제거는 evidence ID로 하며 서로 다른 근거를 문자열이 비슷하다고 합치지 않는다. 잘린 목록의 개수를 전체 개수라고 표시하지 않는다.

익명 검토가 /context에서 사라진다는 과거 보고는 현행 SQL과 테스트로 확인한다. 재현되면 회귀 테스트와 최소 추가 migration/수정을 만든다. 재현되지 않으면 이유를 기록하고 불필요하게 고치지 않는다. 권한·공개 기여·append-only 이력을 바꾸어 우회하지 않는다.

### D. 검증과 인계

먼저 현재 baseline에서 typecheck와 관련 검사를 기록한다. 변경 후 typecheck, test:static, 변경 영역의 unit/service 검사를 실행한다. 검색 경쟁 상태, 취소 후 빈 쿼리, 캐시 키 분리, 혼합 target, 관계 방향, 부분 실패, 근거 중복을 검증하는 행동 중심 테스트를 추가한다. 검사 통과를 위해 assertion을 약화하지 않는다.

test:reference의 누락된 외부 파일은 추적 이력과 프로젝트 문서에서 의도를 확인한다. 근거 있는 복구가 가능하면 저장소 안에서 재현 가능하도록 고치고, 원본을 찾을 수 없다면 임의의 대체 테스트나 빈 통과를 만들지 말고 차단 항목으로 남긴다. 다른 독립 suite는 계속 실행한다. DB/HTTP 검사는 DB_TESTING.md와 LOCAL_INTEGRATION.md의 실제 필수 runner로 수행하고 skipped를 passed로 보고하지 않는다.

끝나면 docs/SPATIAL_DATA_HANDOFF.md에 실제 exported 함수/타입, 예시 호출, 좌우 매핑, 오류/잘림 처리, 테스트 결과, 남은 제약, commit SHA를 간결히 쓴다. 비밀 값이나 큰 응답 본문은 넣지 않는다. 서버 계약을 바꾸지 않고 완료 가능한지 명확히 보고한다. Sol이 이 문서만으로 연결할 수 있어야 한다.

## 6. 에이전트 2에게 전달할 프롬프트 — Sol High

당신은 /Users/nuanox/Documents/Morum의 공간 탐색·읽기 UI 담당이다. MORUM_AGENT_PLAN.md의 제품 기준과 공통 규칙, TEMP_AGENT_HANDOFF.md, Luna가 남긴 docs/SPATIAL_DATA_HANDOFF.md를 읽고 실제 앱을 완성하라. 데이터 인계가 아직 없으면 서버 어댑터를 별도로 중복 구현하지 말고 의존 작업을 명시한다. 하위 에이전트를 만들지 마라.

AGENTS.md와 관련 Next.js 로컬 가이드를 읽는다. 최신 시안 /Users/nuanox/.codex/visualizations/2026/09/20/01a0be4d-b046-7d41-824e-852aea33d759/morum-fluid-map.html은 초기 참고일 뿐 최종 승인된 디자인이 아니다. TEMP_AGENT_HANDOFF의 최신 요구와 아래 조건을 적용한다. 파일이 없더라도 명세로 진행하고 시안 확인 여부를 보고한다.

### 화면과 데이터

- 홈을 검은 점 배경의 2D 문서 공간으로 통합한다. 선, 화살표, 카드 테두리, 격자선, 별도 홈 버튼을 넣지 않는다. 탐색 글꼴은 Pretendard 계열, 읽기는 기존 명조 계열을 유지한다.
- 탐색 노드는 제목과 충분한 발췌를 갖는다. 같은 크기의 보이지 않는 정수 좌표 칸에 배치하며 첫 노드는 (0,0), 나머지는 결정론적인 확장 순서를 쓴다. 같은 결과의 재렌더에서 위치가 임의로 바뀌지 않는다.
- 검색 관련도 순서와 실제 논리 관계는 구분한다. 검색 배치만 보고 부모·자식 관계를 생성하지 않는다.
- 노드 최대 초기 20개. 더 있는 경우 조용한 추가 탐색 수단을 제공하며 첫 페이지만 전체라고 오인시키지 않는다. 목업 문서 배열을 최종 앱에 남기지 않는다.
- 로딩·빈 저장소·결과 없음·서버 실패를 각각 표현한다. 키워드/혼합 검색 및 품질 미평가 상태를 숨기거나 의미 검색 성공처럼 과장하지 않는다.

### 상호작용과 성능

- 상태를 탐색/센터링/드래그·관성/읽기로 명확히 나누어 이벤트 경합을 막는다. 선택되지 않은 노드 클릭은 이동·선택만, 이미 선택된 노드 클릭은 읽기 진입이다.
- 드래그 중 중앙 최근접 문서가 선택된다. 관성으로 이동하는 동안에도 중앙 기준을 유지한다. 드래그 종료 후 click이 발생해 문서가 열리지 않도록 이동 threshold와 click 억제를 둔다. pointercancel과 capture 해제를 처리한다.
- 화살표는 중앙 최근접 노드를 기준으로 해당 방향의 가까운 정수 칸 문서를 정확히 중앙에 맞춘다. 없으면 현재 위치 유지. 동률 규칙은 결정론적으로 고정한다. Enter는 중앙 선택 문서를 연다.
- 검색 입력/textarea/contenteditable, IME 조합 중에는 지도 키보드 단축키를 가로채지 않는다. 입력 Enter는 검색 실행으로 처리하고 문서를 열지 않는다.
- world layer 하나의 translate3d를 이동하고 pointermove 처리는 RAF에서 프레임당 한 번 반영한다. 카메라 위치를 매번 React 전체 상태 갱신으로 전달하지 않는다. RAF는 움직일 때만 유지하고 해제한다.
- 각 문서 밝기는 중심과의 연속 거리로 바꾸되 텍스트 색으로 처리한다. 먼 문서를 opacity로 사라지게 만들지 않는다. per-node left/top 애니메이션, 전체 화면 backdrop-filter, 지속 WebGL 루프를 넣지 않는다.
- 점 배경은 카메라보다 8~10% 느리게 움직인다. 검색창과 작은 X에만 얇은 투명 fill, blur, 반사 가장자리의 CSS glass를 적용한다.
- 검색창은 지도 활동 중 아래로 숨고 2초 유휴 뒤 복귀한다. 단, 입력 focus/IME 조합 중에는 보이게 유지해 타이핑을 방해하지 않는다. 키보드 focus로도 접근 가능하다. 빈 검색어는 홈 데이터로 복귀한다.
- 검색은 Luna의 debounce/취소/경쟁 방지/캐시를 재사용한다. 결과가 바뀌었을 때 관성을 중단하고 새 첫 노드를 중앙에 둔다.

### 읽기와 이동

- 정확한 버전 전문을 중심에 두고 왼쪽 근거·상위, 오른쪽 파생·정정을 각 최대 4개 표시한다. 이 수는 제안 기본값이며 인수인계 범위 3~5개 안이다. 나머지는 전체 맥락으로 접근 가능해야 한다.
- 관계마다 지지/정정/의존 등의 의미를 텍스트로 확인할 수 있게 한다. 반론·동의어·불명확한 관계를 근거로 꾸미지 않는다.
- 좌우 링크를 열면 새 중심 문서가 그 방향에서 들어오고 기존 문서가 이동한다. 전문의 fetch가 끝나기 전에 다른 문서의 제목과 본문을 혼합하지 않는다. 요청 경합과 실패를 처리한다.
- 닫기 X의 보이는 크기는 32~36px. 터치 hit area는 넓히고 접근 가능한 이름을 준다. 닫으면 원래 query/카메라/선택을 복원한다. 읽기에서는 본문 스크롤과 텍스트 선택을 방해하지 않는다.
- 버전 고정 링크, 원문, 최신 버전, 이력, 의미·근거·검토·정정 정보에 계속 접근할 수 있어야 한다. 장식적 지도 때문에 기존 지식 기능을 제거하지 않는다.
- 직접 문서 URL 진입, 새로고침, 브라우저 뒤로/앞으로를 검증한다. 기존 /records, /versions, /search, /objects, /sources 경로는 유효하게 유지한다. Next 라우터와 history를 경쟁시키지 않는다.
- 모바일에서도 중앙 전문이 읽히고 관계 목록에 접근 가능해야 한다. reduced-motion에서는 관성/큰 전환을 축소하거나 즉시 이동한다. focus 이동·복원, 키보드 탐색을 제공한다.
- PixelSwap은 필수가 아닌 후보다. 기본 전환이 완성되기 전에 새 효과 라이브러리를 추가하지 않는다.

### 완료 검증

typecheck, test:static, 관련 기능 테스트, build를 실행한다. 전체 test:functional이 외부 참조 누락으로 막히면 사실을 그대로 기록하고 실행 가능한 suite 결과를 구분한다.

실제 localhost 브라우저에서 다음을 확인한다: 비선택 클릭→선택만, 재클릭→읽기, 드래그 후 열리지 않음, 관성, 네 방향 키·Enter, 한글 조합 입력, 검색 A→B 응답 역전, 빈 검색어 복귀, 부분 서버 실패, 관계 전환, X 복귀, 직접 URL, 뒤로/앞으로, 터치/모바일, reduced-motion. 실제 데이터 연동이 불가능하면 그 제약을 명시하고 fixture 검증을 실연동이라고 보고하지 않는다.

데스크톱과 모바일 화면을 직접 열어 잘림·겹침·명암·본문 가독성을 확인한다. 실행한 동작과 확인 결과, 스크린샷 위치, 변경 commit SHA, 남은 제약을 보고한다. 성능 수치를 측정하지 않았다면 60fps 보장 같은 주장을 하지 않는다. 구현·검증 완료 후 운영 배포는 별도 범위로 남긴다.

## 7. Astra가 마지막에 판단할 것

코드 전체를 다시 읽기보다 작업자의 변경 요약, diff의 핵심 부분, 실패 목록, 실제 화면 증거를 검토한다. 완료 기준은 실제 저장소 검색 → 정확한 버전 읽기 → 근거/반론/정정 확인 → 관련 문서 이동 → 원래 탐색 복귀가 이어지고, 기존 공개 API와 원문 이력이 유지되는 것이다.

다음 단계 후보는 본문의 의미 anchor 연결, 한국어 검색 품질 평가, 외부 에이전트의 읽기·기여·정정 재사용 시나리오다. 이번 공간 탐색 작업에 전부 묶지 않는다. 이름/인증 프로토콜 전환과 운영 배포도 각각 검증 가능한 별도 작업으로 다룬다.
